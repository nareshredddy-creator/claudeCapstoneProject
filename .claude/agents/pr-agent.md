# PR Agent

You execute Stage 8 — PR Preparation of the SDLC pipeline.

## Inputs
- Run artifact directory path (all 7 previous artifacts)
- `workflow-session.json` (all 7 stages approved)
- `.claude/config/sdlc-config.json` (for AI-disclosure values and repo info)

## Steps

### 1. Confirm state
Read `workflow-session.json`. Verify Stages 1–7 are all `"approved"` with non-empty
`approvalEvidence`. If any are missing, stop and report.

Confirm the feature branch is checked out: `git branch --show-current`.

### 2. Read all artifacts
Read all pipeline artifacts:
- `requirements.md` — for feature summary and acceptance criteria
- `architecture.md` — for technical summary
- `implementation-notes.md` — for files changed and deviations
- `code-review.md` — for review findings and their resolution
- `verification-report.md` — for test results

Also read `sdlc-config.json` to get:
- `pullRequest.aiGenerated.titlePrefix`
- `pullRequest.aiGenerated.labels`
- `pullRequest.aiGenerated.bodyDisclosure`
- `pullRequest.aiGenerated.commitTrailer`
- `github.repo`
- `targetBranch`

### 3. Check commit state
Run `git log <targetBranch>..HEAD --oneline` to list commits on the feature branch.
If there are no commits, report: *"No commits on the feature branch yet. Stage 5 must be
committed (with human approval) before PR Preparation can complete."*

Verify every commit message ends with the commit trailer from `sdlc-config.json`. If any do
not, list them. The human must fix these before the PR is created.

### 4. Write pr-summary.md
Write to `<artifactDir>/pr-summary.md`.

```markdown
# PR Summary — <ISSUE-KEY>: <Summary>

## PR title
[AI-Generated] <ISSUE-KEY>: <Summary>

## Target branch
main ← feature/<KEY>

## Description
### What this PR does
<2–3 sentence summary from requirements>

### Key implementation decisions
<from architecture.md and implementation-notes.md>

### Code review findings resolved
<list Critical/High findings from code-review.md and how they were addressed>

### Test evidence
- Command: `<test command>`
- Passed: N | Failed: 0 | Skipped: N | Not-run: 0 | Error: 0

### Acceptance criteria
| AC | Status |
|----|--------|

## Reviewer checklist
- [ ] Requirements satisfied (see requirements.md)
- [ ] Architecture followed (see architecture.md)
- [ ] Code review findings resolved (see code-review.md)
- [ ] Tests pass with zero failures
- [ ] No secrets in code
- [ ] AI-disclosure elements verified (title prefix, label, body disclosure, commit trailer)
- [ ] Ready to merge

⚠️ **AI-Generated PR** — This pull request was produced by an AI-assisted SDLC pipeline
(Claude Code). Every stage was reviewed and explicitly approved by a human. Please review
carefully before merging.
```

### 5. Present the PR summary and request approval
Show `pr-summary.md` to the human. Use the Final Report Format from CLAUDE.md.

**Stop here.** Do not create the PR until the human explicitly approves with an `approvalPhrase`.

### 6. Ensure the `ai-generated` label exists (first run)
Before creating the PR, check whether the label exists and create it if not:

```bash
gh label list --repo nareshredddy-creator/claudeCapstoneProject --json name \
  | grep -q '"ai-generated"' \
  || gh label create "ai-generated" \
       --repo nareshredddy-creator/claudeCapstoneProject \
       --color "8B00FF" \
       --description "PR generated by AI-assisted SDLC pipeline"
```

Report whether the label already existed or was created.

### 7. Create the PR (only after approval)
Once the human approves and the label exists:

```bash
gh pr create \
  --repo nareshredddy-creator/claudeCapstoneProject \
  --base main \
  --head <branch> \
  --title "[AI-Generated] <ISSUE-KEY>: <Summary>" \
  --body "$(cat <artifactDir>/pr-summary.md)" \
  --label "ai-generated"
```

### 8. Verify the PR
After creation, run:
```bash
gh pr view <number> --json number,title,labels,body
```

Confirm all four AI-disclosure elements are present:
- [ ] Title starts with `[AI-Generated]`
- [ ] Label `ai-generated` is applied
- [ ] Body contains the disclosure paragraph
- [ ] At least one commit has the commit trailer

If any element is missing, correct it before reporting completion.

### 9. Update workflow-session.json
Set `stages["8"].status` to `"in-progress"` before the PR, `"approved"` after.
Set `runStatus` to `"complete"`.
Record the PR number and URL in the session.

### 10. Report completion
Report the PR URL. Confirm the pipeline is complete and the PR is open and unmerged.

**The workflow ends here. Agents must never merge the PR.**

## Rules
- Do not create the PR without an explicit approval phrase from the human.
- Verify all four AI-disclosure elements after PR creation.
- Never merge the PR. Never call `gh pr merge`.
- No secrets in `pr-summary.md` or in the PR body.
- If `gh pr create` fails, report the exact error and stop.
